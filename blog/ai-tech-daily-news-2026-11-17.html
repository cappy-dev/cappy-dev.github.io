AI & Tech Daily News, November 17, 2026

Free computer science lectures, a closer look at a Microsoft 365 outage, and a serious web-script compromise lead today’s report. Linux firmware, Rust compilation, and a new Rust datetime release round it out.

Free computer science lessons from Carnegie Mellon

Carnegie Mellon’s CS Learn page points to a new set of free classroom lectures on YouTube. The page describes full lectures by university faculty, with the first premieres scheduled for November. A separate self-paced learning feature is marked as coming next, so the offer is growing in stages rather than arriving as a complete online course catalog on day one. That distinction matters for anyone looking for a structured class: lectures can be useful on their own, but they do not automatically include assignments, feedback, or a course sequence. Still, free access to actual university lectures is an easy way to sample a subject before paying for a course or committing to a program.

How three failures combined in Microsoft 365

Microsoft’s explanation of a global outage describes a failure with more than one cause. A software bug, traffic shifting, and reduced capacity interacted, leaving the service with fewer safe options for handling demand. This kind of incident is hard to prevent with a single patch. The bug matters, but so does how traffic moves when one region or system has trouble, and how much spare capacity remains when that shift happens. Ars says Microsoft plans to publish its full final incident report on November 20. That report may clarify why regional isolation systems failed and what corrective steps the company will take. Until then, this is a useful reminder that reliability depends on failure handling as much as on normal operations.

A compromised marketing script put visitors at risk

Report URI’s account of the Optimizely incident says malicious JavaScript reached visitors on sites operated by 178 organizations. The list included Zoom, the BBC, CNN, Salesforce, GitLab, IKEA, HSBC, Equifax, Air France-KLM, Ledger, and Peacock. The payload could replace cryptocurrency wallet addresses, steal payment-card details and cookies, capture screenshots, and deliver iOS exploit kits to some visitors. The report says most malicious snippets had been cleaned up by the time of its later checks, but the cause of the attacker’s access remained unknown. This is a sharp example of supply-chain exposure through a tool that many visitors never notice. A site can carefully protect its own code and still run a script managed through a vendor account. Organizations using client-side experimentation tools should review the snippets they serve and the access that can change them.

AlmaLinux 10.3 restores ModSecurity

AlmaLinux 10.3 brings ModSecurity back alongside other release updates. For teams that use AlmaLinux as a server platform, the return of a familiar web application firewall component may be more relevant than a long feature list. ModSecurity can help inspect and filter web requests, though its rules need maintenance and can produce false positives if deployed without testing. Administrators should check the release notes and their own package configuration before upgrading production systems. A version number alone does not tell you whether a change affects an installed service, a custom module, or a locally managed rule set. The practical work is the usual one: test the update on a representative host, confirm the security component behaves as expected, then schedule the wider rollout.

Firmware support reaches Synaptics touchpads

fwupd 2.1.10 adds support for Synaptics touchpads and includes fixes. Firmware updates for touchpads do not draw the same attention as graphics or storage releases, but input hardware can carry bugs that are difficult to work around in software. fwupd gives Linux users and system vendors a shared path for delivering device firmware, provided the hardware vendor publishes suitable update metadata and packages. The addition does not mean every Synaptics touchpad can now receive updates, so users should check whether their exact device appears in the supported-hardware information. For administrators, the release is another reason to keep the firmware update service current, while still testing on the hardware models they actually manage.

Rust tests parallel compilation in nightly

Rust nightly is moving toward enabling its parallel frontend by default, giving more users a chance to exercise the feature before stabilization. Rust already parallelizes parts of compilation, but frontend work has generally run sequentially by default. The project’s published benchmarks show faster builds with multiple frontend threads, though the gain will vary with the codebase, processor, and available cores. The option can also be adjusted with --jobs-frontend=. Nightly is the right place for this kind of change: compiler developers get broader testing, while production users can wait until behavior and performance settle. If you maintain a large Rust workspace, it is worth trying the nightly option on a repeatable build and comparing wall-clock time. A shorter build is useful, but only if diagnostics and build results stay dependable.

Jiff reaches 1.0

Jiff 1.0 gives Rust developers a datetime library with time zones and daylight-saving behavior at the center of its design. Those details are where date handling tends to go wrong: adding a day is not always the same as adding 24 hours, and local clock times can be ambiguous when daylight-saving transitions happen. Jiff’s author says the library is already used in projects including Cargo, uv, Starship, fd, Nushell, mise, and Jujutsu. The 1.0 label also comes with a commitment to keep the API stable unless a significant defect turns up. That gives teams a clearer basis for depending on it, though choosing a date library still means weighing its API and calendar scope against the needs of a project. Jiff supports the Gregorian calendar, so applications that need other calendars should look elsewhere.
