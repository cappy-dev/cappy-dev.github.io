DeepSeek V4 Pro launched and the numbers are wild

DeepSeek LLM AI Coding

DeepSeek released V4 Pro 0813 today. It took the top spot on Hacker News with 870+ points and 350 comments in a few hours. People are throwing real coding tasks at it and coming back with opinions.

Here is what makes this release interesting: the benchmark gains over the V4 Pro Preview are enormous, the price is roughly 20x cheaper than Claude Opus 4.8, and DeepSeek is already warning that prices will go up.

What changed from Preview to 0813

The V4 Pro Preview shipped a few weeks ago. The 0813 checkpoint is a big jump, not a small one. On Terminal Bench 2.1, it went from 72.1 to 87.9. On DeepSWE, it went from 12.8 to 62.7. That is not a gradual improvement. That is a model that suddenly got a lot better at agentic coding tasks.

The NL2Repo score jumped from 38.5 to 61.5. DSBench FullStack went from 41.8 to 71.1. If you were testing the Preview and wrote it off, you need to look again.

How it compares

A Hacker News commenter posted a detailed benchmark comparison pulled from the r/LocalLLaMA subreddit. The numbers put V4 Pro 0813 next to GLM-5.2, Kimi-K3, Claude Opus 4.8, and Fable 5.

On Terminal Bench 2.1, Kimi-K3 leads at 88.3, with DeepSeek V4 Pro close behind at 87.9. Fable 5 sits at 88.0. Opus 4.8 is at 85.0. These are all within spitting distance of each other.

On HLE (without tools), DeepSeek scores 42.7. Opus 4.8 gets 49.8. Fable 5 gets 53.3. Kimi-K3 gets 43.5. DeepSeek is competitive but not the top model on pure reasoning.

On DeepSWE, the benchmark for software engineering agents, the story is different. Kimi-K3 leads at 67.5. Fable 5 is at 70.0. DeepSeek V4 Pro 0813 sits at 62.7. Opus 4.8 is at 58.0. The gap between DeepSeek and the leaders is real but closing fast.

Where DeepSeek clearly wins is the ratio of capability to cost.

The cheaper tier, still good for most tasks

For context, Claude Opus 4.8 costs around $15 per million input tokens and $75 per million output. DeepSeek V4 Pro at $0.435/$0.87 is roughly 20x cheaper on output. The cache hit price for input tokens is $0.003625 per million. That is basically free. If your app sends the same system prompt repeatedly with small variations, DeepSeek will cost you almost nothing for input tokens after the first request.

The Flash model is even cheaper at $0.14/$0.28. Several Hacker News commenters said Flash is the model they actually use day to day, and that it remains the best value of any frontier model right now.

What real users say

The HN thread has people running actual workloads, not just posting benchmark screenshots. One commenter ran the same feature development task on both DeepSeek V4 Pro and Grok 4.6 using Codex CLI. DeepSeek took 12 minutes and cost $0.12 but shipped a bug. Grok took 3 minutes, cost $1.41, and shipped clean code. That is the tradeoff in a nutshell: DeepSeek is absurdly cheap but you may need a second pass.

Another commenter spent $12.50 running V4 Pro on their traffic simulator and distributed physics engine for a full day. They found "significant gains without introducing any new problems." That is a real person using it for real work and walking away happy.

A third user called it solid as an auditor for implementations, saying they will split work between Claude Sonnet 5.6 and DeepSeek Pro going forward.

Not everything is rosy. One commenter pointed out that DeepSeek models score badly on ArtificialAnalysis's hallucination rate and AA-Omniscience benchmarks. They wondered if the model is over-indexing on coding at the expense of factual accuracy. Nobody in the thread had a strong counterargument. If your use case involves generating factual content rather than code, this is worth watching.

The catch

DeepSeek posted a notice on their pricing page: "We plan to raise the overall pricing for DeepSeek API services in the near future, with a significant increase expected."

They do not say when or how much. The current prices are clearly a loss leader or at best break-even. A 2.4T parameter MoE model with 1M context, serving at $0.435 per million input tokens, is not sustainable at scale. Someone is subsidizing this.

The other catch is data privacy. As of launch, the only OpenRouter provider endpoint for V4 Pro requires enabling "Allow paid endpoints that train on request data" in privacy settings. Multiple commenters said they will wait for a provider that does not train on prompts before benchmarking. If you are sending proprietary code through the API, read the fine print.

Specs

Both V4 Pro and V4 Flash support 1M token context with up to 384K output tokens. They support thinking and non-thinking modes, JSON output, tool calling, the OpenAI Responses API format, and the Anthropic API format. The Anthropic API compatibility is notable. You can point your existing Claude client at DeepSeek's endpoint and it just works.

Concurrency limits: 2,500 for Flash, 500 for Pro. That is generous. Most API providers cap at 10-50 concurrent requests for cheaper tiers.

Should you try it

If you are paying for Claude Opus or even Sonnet for coding tasks, you should test DeepSeek V4 Pro. The cost difference is so large that even if you need a human review pass or a second model to catch bugs, you will likely still come out ahead.

If you are doing factual generation, summarization, or anything where hallucination matters, wait for independent hallucination benchmarks. The coding numbers are great. The AA-Omniscience numbers are not.

If you are already using V4 Flash for daily work, the Flash model did not change in this release. The Flash 0731 checkpoint is still the value king. Pro 0813 is for when you need the extra agentic muscle.

DeepSeek has been shipping at a pace that makes Western labs look slow. V4 Preview, then Flash, now Pro 0813, each a real improvement over the last. The question is whether the price holds. Right now, the answer is no. But while it does, you might as well use it.
